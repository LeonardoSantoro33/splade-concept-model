# Step-by-step guide: how every result was produced

This guide lists, in execution order, the commands used to produce the results in the README, on a Slurm cluster
(ISTI-CNR, A100 40 GB nodes, partition `long`). All commands are run from the repository directory. Result tables
are in [`RESULTS.md`](RESULTS.md); the exact hyper-parameters of the final checkpoints are in its first section.

> Raw logs and per-query results (`logs/`, `training_logs/`, `results/`) are not in the repository: see [Reproducibility](../README.md#reproducibility) in the README.

| Stage | What it does | Script |
|---|---|---|
| Baseline | SPLADE with exact search over all of MS MARCO | `04_baseline_splade.py` |
| Model | Concept Model `g(x) = W·SPLADE(x)`, score `g(q)·g(d)` | `concept_model.py` |
| Training | **frozen** (only W) and **e2e** (W and BERT) variants, InfoNCE | `06_train_concept_model.py --mode frozen / e2e` |
| Negatives | in-batch + hard negatives mined with SPLADE (exact search) | `07_mine_negatives.py --miner splade` |
| Evaluation in domain | MS MARCO dev, TREC DL19, DL20 | `08`, `08b`, `08c` |
| Evaluation out of domain | zero-shot BEIR (NFCorpus, SciFact, FiQA) | `10_eval_beir.py` |
| Hybrids | mix with SPLADE, λ chosen on validation | `11_eval_hybrid.py` |
| Statistics | paired per-query tests | `12_significance.py` |
| Legacy | LCE baseline of the earlier SPLARE project | `09_lce_splade.py`, `lce.py` |

## 0. Before you start (once)

```bash
git clone https://github.com/LeonardoSantoro33/splade-concept-model.git
cd splade-concept-model
mkdir -p logs                     # Slurm writes the job logs here
conda create -n splade python=3.11 && conda activate splade
pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu118
pip install -r requirements.txt   # or requirements_env.txt for the exact environment
```

**Data directories.** Both paths are read from environment variables (defaults in `config.py`); put them in
`~/.bashrc` so they are always set:

- `FM_DIR`: pre-encoded SPLADE vectors of MS MARCO in Seismic format (`documents.bin`, `queries.bin`, `doc_ids.npy`,
  `queries_ids.npy`, `token_to_id_mapping.json`, `groundtruth_100.tsv`). **Only read, never modified.** These files
  were provided to us and are not public; they can be regenerated by encoding MS MARCO with
  `naver/splade-cocondenser-ensembledistil`.
- `WORK_DIR`: scratch space for caches, models and results. Layout after all experiments:
  `models/` (checkpoints, ~110 GB), `embeddings/` (~110 GB), `runs/` (TREC files), `cache/`, `msmarco/`, `beir/`,
  `negatives/`, `results/` (one `.json` per run and query set), `encoder_check.json`.

```bash
export FM_DIR=/path/to/pre-encoded/splade
export WORK_DIR=/path/to/scratch/$USER/splade_concept
```

**Submitting jobs.**

```bash
sbatch [--export=ALL,PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True] --time=HH:MM:SS -J NAME jobs/gpu.sbatch SCRIPT.py --args
sbatch --time=00:15:00 -J NAME jobs/cpu.sbatch SCRIPT.py --args
squeue -u $USER                        # status
tail -f logs/NAME_<jobid>.out          # follow the log (Ctrl+C leaves the job running)
scancel <jobid>
```

Logs are `logs/<job name>_<job id>.out` / `.err`. Partition names may need to be adapted to your cluster.
Do not `cat` the large result `.json` files on a cluster terminal; `grep` the log lines instead.

**Naming of results.** Every evaluation writes `results/<run>_<set>.json` with per-query metrics, for example
`..._best_dev.json`, `..._best_beir_fiqa.json`, `splade_baseline_dev.json`, `hyb_e2e_k256_..._best_lam0.20_dev.json`.
Hybrid validation curves are in `*_validation.json`; significance tests in `results/significance/` and
`results/significance.csv`.

## 1. Data and baseline

### 1.1 Smoke test on synthetic data (5 minutes, CPU)

```bash
srun -p long -c 4 --mem=16G -t 00:30:00 python -u 00_smoke_test.py
```

Must end with `ALL TESTS PASSED (9)`. It runs every stage on a tiny synthetic corpus, so bugs show up in minutes.
(It imports `lce.py`, which is why that legacy module stays in the repository.)

### 1.2 Prepare the provided data (~15 min, CPU)

```bash
sbatch -J prep jobs/cpu.sbatch 01_prepare_data.py
```

Converts the token ids of the provided vectors (28,679-entry mapping) into the BERT space (30,522) and caches the
8.84M documents and the 6,980 dev queries. Check in the log: the document and query counts, and
`dot-product check: groundtruth=X recomputed=X` (the two numbers must match).

### 1.3 Download MS MARCO and TREC DL (~10 min, network, login node is fine)

```bash
python -u 02_download_msmarco.py --trec-dl
```

### 1.4 Which SPLADE model made the provided vectors? (~5 min, GPU)

```bash
srun -p long -c 4 --mem=32G --gpus 1 -t 00:30:00 python -u 03_check_encoder.py
```

Must print `GOOD: same model`. We obtained cosine 1.0000 for `naver/splade-cocondenser-ensembledistil`
(and 0.88 for `selfdistil`, which is therefore not the one). The result is saved in `WORK_DIR/encoder_check.json`
and used by scripts 04 and 05.

### 1.5 SPLADE baseline (~10 min, GPU)

```bash
sbatch -J baseline jobs/gpu.sbatch 04_baseline_splade.py --query-sets dev dl19 dl20
```

Expected on dev: MRR@10 = 0.3828, nDCG@10 = 0.4489, R@1000 = 0.9831, and
`Overlap with the provided groundtruth ... (expected ~1.00)`. If the overlap is low, stop: data and ids are not aligned.

### 1.6 Encode the training queries (~10 min, GPU)

```bash
sbatch -J enc_train jobs/gpu.sbatch 05_encode_train_queries.py
```

Encodes the 503k training queries that have a qrel. 1,000 of them are held out for validation (seed 42) and never used
for training.

## 2. Frozen variant (only W is trained)

Round 1 uses in-batch negatives only, round 2 adds 7 hard negatives per query (ranks 4–100 of SPLADE; the top 3
are discarded as possible false negatives):

```bash
sbatch -J mine_splade jobs/gpu.sbatch 07_mine_negatives.py --miner splade --out splade     # ~1 h

sbatch -J cm_r2_k1024_lr3e5 jobs/gpu.sbatch 06_train_concept_model.py --mode frozen --k 1024 \
       --run-name frozen_k1024_r2_lr3e5 --negatives splade --n-hard 7 --neg-rank-min 3 \
       --lr 3e-5 --epochs 2 --val-every 100
```

What we learned while tuning (validation MRR@10, 1,000 queries, SPLADE = 0.3639):

- in-batch negatives only (round 1) ends *below* a random W for k ≥ 512; hard negatives help at every k;
- the original learning rate (1e-3) was too high and destroyed the random projection: lowering it was the main fix;
- `--init-std = 1/√k` fixes the initial score scale (loss at step 0 at k = 256: 6.08 → 1.86) and was used for k ≥ 512
  (k = 256 and 1024 kept the best older recipe);
- discarding more candidates (`--neg-rank-min 20`) and lowering the temperature (0.1, 0.05) did **not** help;
- for k = 2048, 4096, 8192: `--init-std 0.0221 / 0.0156 / 0.0110 --lr 3e-5 --epochs 5 --val-every 250`.

The **random-W baseline** is the same architecture with W left at its initialisation (`init-std = 1/√k`), obtained by
running the training for one step with a negligible learning rate; the checkpoints are named `frozen_k<k>_rand`:

```bash
sbatch -J cm_rand_k1024 jobs/gpu.sbatch 06_train_concept_model.py --mode frozen --k 1024 --run-name frozen_k1024_rand \
       --negatives splade --n-hard 7 --neg-rank-min 3 --init-std 0.03125 --lr 1e-9 --max-steps 1
```

The final checkpoint of each k and its hyper-parameters are listed in [`RESULTS.md`](RESULTS.md).

### Official evaluation (dev, DL19, DL20)

```bash
sbatch -J eval_k1024 jobs/gpu.sbatch 08_eval_concept_model.py --ckpt frozen_k1024_r2_lr3e5 \
       --query-sets dev dl19 dl20 --explain 5
```

`08` builds dense document vectors, which fit in 40 GB up to k = 1024. For larger k use the streaming version
(`08b_eval_streaming.py`, with `--ckpt` and `--query-sets`; no `--explain`), which uses `g(q)·g(d) = (Wᵀg(q))·SPLADE(d)` and never builds the dense matrix.
Streaming gives the same numbers up to fp16 rounding (differences ≤ 0.0006 on k = 1024).
`--explain N` also writes `concepts_<name>.tsv` (top tokens of each concept) and N interventions.

## 3. End-to-end variant (W and BERT are trained)

Same loss and negatives, plus `--mode e2e` and a second learning rate for BERT (`--lr-backbone`). Batch size 32,
one epoch (~15,700 steps, ~2 h 40 on an A100), gradient checkpointing to avoid out-of-memory:

```bash
sbatch --export=ALL,PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True --time=05:00:00 \
       -J cm_e2e_k1024 jobs/gpu.sbatch 06_train_concept_model.py --mode e2e --k 1024 \
       --run-name e2e_k1024_r2_is03125_lr3e5_bb5e6_b32_ep1 --negatives splade --n-hard 7 --neg-rank-min 3 \
       --init-std 0.03125 --lr 3e-5 --lr-backbone 5e-6 --batch-size 32 --epochs 1 \
       --val-every 2000 --val-queries 1000 --grad-checkpointing
```

Search protocol: a grid over the W learning rate and the BERT learning rate at 1 epoch; the best validation score wins,
differences below 0.001 are treated as ties (the lower BERT learning rate wins; this threshold was fixed during the
experiments, not beforehand); if the winner is at the edge of the grid, the grid is extended. Two epochs were never
better than one (k ≤ 1024), so one epoch was used everywhere. The optimal BERT learning rate falls as k grows:
1e-5, 5e-6, 5e-6, 5e-6, 1e-6, 1e-7 for k = 256 … 8192.

**e2e with fixed W** (k = 1024): same command with `--lr 1e-9` (W does not move), to tell whether the gain comes from W or BERT.

### Evaluation: it needs the whole corpus re-encoded

The re-trained encoder changes the SPLADE vectors of all 8.84M passages (~1 h). `08c` does this in streaming (exact search,
no dense matrix) and saves the sparse shards of the new encoder, which the hybrid scripts reuse:

```bash
sbatch --export=ALL,PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True --time=10:00:00 -J eval_e2e_stream_k4096 \
       jobs/gpu.sbatch 08c_eval_e2e_streaming.py --ckpt e2e_k4096_r2_is0156_lr3e5_bb1e6_b32_ep1 --query-sets dev dl19 dl20
```

The job resumes from the saved chunks if it is interrupted. If the GPU runs out of memory, use `--batch-size 16` or
`--grad-checkpointing`.

## 4. Out of domain: BEIR (zero-shot)

```bash
python -u 10_eval_beir.py --datasets nfcorpus scifact fiqa --download-only
sbatch --time=01:00:00 -J beir_splade jobs/gpu.sbatch 10_eval_beir.py --datasets nfcorpus scifact fiqa --splade
sbatch --time=01:00:00 -J beir_frozen_k1024 jobs/gpu.sbatch 10_eval_beir.py --datasets nfcorpus scifact fiqa \
       --ckpts frozen_k1024_r2_lr3e5
```

`--ckpts` accepts random-W, frozen and e2e checkpoints. No model is re-trained on BEIR. `--ft-splade` evaluates the
re-trained encoder of an e2e checkpoint as a plain SPLADE (W discarded).

## 5. Hybrids

Score `(1-λ)·SPLADE(q)·SPLADE(d) + λ·g(q)·g(d)`. `11_eval_hybrid.py` runs in a single job:

1. Exact search on the 1,000 validation queries for 21 values of λ (0, 0.05, …, 1) → λ\* = the best MRR@10
2. Dev, DL19 and DL20 with λ\*, plus the checks λ = 0 (must reproduce SPLADE, 0.3828) and λ = 1 (must reproduce the
   Concept Model alone)

```bash
# frozen: only SPLADE's index and W are needed
sbatch -J hyb_frozen_k256 jobs/gpu.sbatch 11_eval_hybrid.py --ckpt frozen_k256_r2 --query-sets dev dl19 dl20

# e2e: run 08c first (it saves the sparse shards of the re-trained encoder), then the hybrid
sbatch -J hyb_e2e_k256 jobs/gpu.sbatch 11_eval_hybrid.py --ckpt e2e_k256_r2_is0625_lr1e4_bb1e5_b32_ep1 --query-sets dev dl19 dl20
```

The `--variant` option (e2e checkpoints only) selects what is mixed:

| Name in the results | `--variant` | Score | Indexes |
|---|---|---|---|
| `hyb_…` | `two` (default) | `(1-λ)·SPLADE·SPLADE + λ·g·g` | 2 |
| `hyb1_…` | `single` | `(1-λ)·SPLADE_θ·SPLADE_θ + λ·g·g` | 1 |
| `hybnoW_…` | `now` | `(1-λ)·SPLADE·SPLADE + λ·SPLADE_θ·SPLADE_θ` (no W) | 2 |
| `ftsplade_…` | (`single` with λ = 0) | `SPLADE_θ·SPLADE_θ` | 1 |

`SPLADE_θ` is the re-trained encoder. The variants only reuse the shards written by `08c` and take about 5 minutes.

Hybrids on BEIR use the λ\* found on MS MARCO validation (nothing is chosen on BEIR):

```bash
sbatch --time=01:00:00 -J beir_hyb_k256 jobs/gpu.sbatch 10_eval_beir.py --datasets nfcorpus scifact fiqa \
       --hybrid e2e_k256_r2_is0625_lr1e4_bb1e5_b32_ep1:now:0.40
```

## 6. Significance tests

```bash
sbatch --time=00:15:00 -J sig_hybnoW256 jobs/cpu.sbatch 12_significance.py \
       --a splade_baseline_dev --b hybnoW_e2e_k256_r2_is0625_lr1e4_bb1e5_b32_ep1_best_lam0.40_dev
```

It reads the per-query metrics saved in `results/` (no search, no GPU, a few seconds) and, for MRR@10, nDCG@10 and
R@1000, prints the mean of each system, the difference B − A, a 95% bootstrap confidence interval (10,000
resamples) and p-values from a paired t-test and a paired permutation test (10,000 sign flips). Conventions:

- **A is the reference, B the system under test**, so B − A > 0 means B is better
- We call a difference **significant** only if the two-sided permutation p-value is below 0.05 and the 95% bootstrap confidence interval of B − A does not contain zero
- We test only where an improvement is claimed

For BEIR, A and B are `splade_baseline_beir_beir_<dataset>` and `<run>_beir_<dataset>`.

## 8. Design choices to report

- **Exact search instead of ANN**: every number is an upper bound for any approximate index, with no approximation error.
- **Clean validation**: 1,000 training queries held out; checkpoints, hyper-parameters and λ are chosen on them
  (re-ranking SPLADE's top 100 during training, full-corpus search for λ), never on dev or BEIR.
- **False negatives**: the other known positives of the same query are masked out of the negatives in the loss, and the top 3 mining
  candidates are discarded (`--neg-rank-min 3`).
- **SPLADE pooling**: `log(1 + ReLU(max_i logits_i))` instead of `max_i log(1 + ReLU(logits_i))`. Same result, but less memory: log/ReLU run after the max.

## 9. Troubleshooting

| Message | What to do |
|---|---|
| `CUDA out of memory` | lower `--batch-size` (training) or `--q-batch` (search); use `--grad-checkpointing` and `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`; for k ≥ 2048 use the streaming evaluation (`08b` / `08c`) |
